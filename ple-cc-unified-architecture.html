↗️ เปิดเต็มจอ
1. เมื่อตัวจับเวลานับถอยหลังถึง 00:00 Fix Point 1
เงื่อนไขเหตุการณ์: เมื่อ SimState.timerValue ลดลงจนน้อยกว่าหรือเท่ากับ 0 ในฟังก์ชัน startLocalCountdown
พฤติกรรมเดิม (สาเหตุบั๊ก): สั่ง clearInterval แต่ลืมตั้ง SimState.timerRunning = false ทำให้สถานะยังค้างว่าจับเวลาอยู่
พฤติกรรมที่ถูกต้อง (Fix 1): ตั้งค่า SimState.timerRunning = false ทันที เพื่อป้องกันไม่ให้ applyRoomState สร้าง Timer ซ้ำเมื่อมี Snapshot ส่งเข้ามา clearInterval(SimState.timerInterval); SimState.timerRunning = false;
2. หน้าต่างแจ้งหมดเวลา (3-Second Window) Fix Point 2
เงื่อนไขเหตุการณ์: เมื่อเวลาแตะ 00:00 ฟังก์ชัน showTimeoutPopup ถูกเรียกเพื่อเปิด Modal นับถอยหลัง 3 วินาที
จุดเสี่ยง Race Condition: หากมี Snapshot เข้ามาระหว่าง 3 วินาทีนี้ showTimeoutPopup อาจถูกเรียกซ้อน ส่งผลให้มี Callback เลื่อนสถานีทำงานพร้อมกัน 2 ตัว
มาตรการป้องกัน: เพิ่มตัวแปรล็อกและตรวจสอบ ID หากมี overlay-timeout อยู่แล้ว จะไม่สร้างใหม่และยกเลิก callback ซ้ำ if (document.getElementById('auto-timeout-overlay')) return;
3. สิทธิ์การสั่งเปลี่ยนสถานีในโหมด Cohort Fix Point 3
เงื่อนไขเหตุการณ์: เมื่อฟังก์ชัน jumpToStation ถูกสั่งทำงานในห้องสอบแบบ Cohort Breakout
กฎการควบคุม (Access Control): เฉพาะ Super Host เท่านั้นที่มีสิทธิ์เขียน currentStationIdx ลง Firebase ส่วน Examiner ประจำโต๊ะห้ามแตะเด็ดขาด
โค้ดบังคับใช้: if (SimState.examMode === 'cohort_breakout' && SimState.isLobby && !SimState.isHost) return;
4. การปิดการสอบ (Results Transition Lock) Fix Point 4
เงื่อนไขเหตุการณ์: เมื่อห้องสอบได้รับ status = 'results' จาก Firebase ใน applyRoomState
จุดเสี่ยงเดิม: สั่ง await finishExamSimulation() โดยไม่ได้ล็อก isFinishingExam ไว้ล่วงหน้า ทำให้ Snapshot อื่นเรียกซ้อนได้
มาตรการป้องกัน: ตั้งค่า SimState.isFinishingExam = true ก่อนเข้าสู่คำสั่ง async finishExamSimulation() SimState.isFinishingExam = true; await finishExamSimulation();
5. กรรมการกดย้อนดูสถานีก่อนหน้า (Local View) Feature Logic
สิทธิ์การแสดงปุ่ม: แสดงเฉพาะ Examiner ในโหมด Cohort Breakout เท่านั้น ส่วน Examinee และ Super Host จะไม่เห็นปุ่มนี้เลย
การแยกสถานะ (State Isolation): เก็บค่าลงใน SimState._localReviewIdx โดยไม่เปลี่ยนสถานะของห้องสอบใน Firebase
การแสดงผลหน้าจอ: แสดงแบนเนอร์เตือนสีส้ม "โหมดดูย้อนหลัง: คุณกำลังดูสถานีที่ X (ห้องสอบกำลังอยู่ที่สถานีที่ Y)" พร้อมปุ่มกดกลับสถานีปัจจุบัน
6. การติ๊กคะแนนขณะอยู่ในโหมดดูย้อนหลัง Data Integrity
คำถามสำคัญ: คะแนนจะถูกบันทึกไปทับสถานีปัจจุบันของห้องสอบหรือไม่?
คำตอบทางเทคนิค: ไม่ทับแน่นอน เพราะฟังก์ชัน updateLobbyChecklistOnServer อิงหมายเลขสถานีตามเคสที่กำลังเปิดดูอยู่ (SimState.stations[currentIdx].stationNumber)
พาทข้อมูล Firebase: rooms/[roomId]/breakouts/[tableId]/scores/[viewedStationNumber]
7. การดึงกรรมการกลับอัตโนมัติ (Auto Snapback) UX Guard
เงื่อนไขเหตุการณ์: กรรมการกำลังย้อนดูสถานีที่ 2 แต่ Super Host กดสั่งเปลี่ยนจากสถานี 3 ไปยังสถานี 4
กลไกการทำงาน: เมื่อ Firebase ส่ง Snapshot ที่มี targetIdx ใหม่เข้ามา ระบบจะตรวจพบว่า stationChanged เป็น true
ผลลัพธ์: ระบบจะล้างค่า SimState._localReviewIdx = null และสั่ง renderStation(targetIdx) เพื่อพากรรมการกลับมาสถานีที่ 4 ทันที พร้อมแสดง Toast แจ้งเตือน
8. การป้องกันหน้าจอผู้เข้าสอบ (Examinee Guard) Isolation
ข้อกำหนดเข้มงวด: ผู้เข้าสอบต้องไม่ได้รับผลกระทบใดๆ เมื่อกรรมการกดย้อนดูสถานีเก่า
การควบคุม: หน้าจอผู้เข้าสอบอิงตาม room.currentStationIdx จาก Firebase เสมอ ไม่รู้จักตัวแปร _localReviewIdx และไม่แสดงปุ่มย้อนดู
ความปลอดภัย: ผู้เข้าสอบยังคงเห็นโจทย์และเวลาของสถานีปัจจุบันตามจริง 100%
9. หลุดจากหน้าจอแล้วกลับมาจอยห้องสอบเดิม Session Reconnect
กลไกการจำสถานะ: เมื่อผู้เข้าสอบหรือกรรมการหลุด ปิดแท็บ หรือกดรีเฟรช ระบบเก็บ ple_session_player_id และ ple_session_room_id ใน Session Storage
การคืนที่นั่งโต๊ะย่อย (Table Re-seat): ฟังก์ชัน autoReconnectCohortSession ตรวจพบ existingById หรือ existingByName และคืนค่า SimState.myBreakoutTableId และบทบาทเดิม (examiner/examinee) ทันที
ข้ามจอนับถอยหลังทันที: หากการสอบกำลังดำเนินอยู่ (room.status === 'running') ระบบจะบายพาสจอนับถอยหลัง 5-4-3-2-1 และพาเข้าสู่สถานีปัจจุบัน พร้อมกู้คืน Checklist ที่เคยตรวจค้างไว้ทั้งหมด 100% const isExistingMember = Boolean(existingById || existingByName);
10. ระบบล็อคห้องสอบ (Host Room Lock 🔒) Security Barrier
การสั่งงาน: ผู้คุมสอบ (Host หรือ Super Host) กดปุ่มไอคอนกุญแจ 🔒 เพื่อสั่ง toggleRoomLock() ซึ่งจะส่ง isLocked: true ไปยัง Firebase RTDB
การบล็อกบุคคลภายนอก: หากบุคคลใหม่พยายามเข้าห้องสอบ ระบบจะแสดง Modal: "🔒 ห้องสอบถูกล็อกโดยผู้คุมสอบ - ห้องสอบปิดรับสมาชิกใหม่ (Room Locked)"
ข้อยกเว้นพิเศษ (Bypass Rule): สมาชิกเดิมที่มีชื่ออยู่ในห้องแล้ว (isExistingMember === true) จะได้รับการยกเว้นและสามารถกลับเข้าห้องได้เสมอแม้ห้องจะถูกล็อคอยู่ก็ตาม if (roomData.isLocked && !isExistingMember) { showRoomBlockedModal(...); }
11. ชื่อไม่ตรง / ชื่อซ้ำเข้าไม่ได้ (Name Guard) Identity Integrity
การป้องกันชื่อชนกันใน Lobby: ในขั้นตอนรอสอบ (status === 'setup') หากมีคนใหม่พิมพ์ชื่อซ้ำกับผู้ที่มีอยู่ในห้อง ระบบจะปฏิเสธด้วยการแจ้งเตือน: "ชื่อนี้มีผู้ใช้งานอยู่ในห้องสอบนี้แล้ว กรุณาใช้ชื่ออื่น"
การป้องกันการนั่งทับโต๊ะ (Seat Conflict): ระบบตรวจสอบ targetTable.examinerName และ targetTable.participantName เพื่อไม่ให้เกิดการนั่งซ้อนทับกันที่โต๊ะสอบย่อย
การกู้คืนด้วยชื่อเดิม: หากผู้สอบเปิดอุปกรณ์ใหม่แต่ไม่มี Session Storage เดิม หากพิมพ์ "ชื่อเดิมที่ถูกต้อง" ระบบจะแมตช์ existingByName และกู้คืน Player ID เดิมให้ทันที if (roomData.status === 'setup' && !existingById && existingByName) { alert(...); }
12. ห้องสอบเริ่มแล้วห้ามเข้า (Mid-Exam Barrier) Exam Integrity
เงื่อนไขเหตุการณ์: เมื่อสถานะห้องสอบเปลี่ยนเป็น status === 'running' หรือ status === 'countdown'
การบล็อกคนใหม่: บุคคลที่ไม่ได้อยู่ในรายชื่อเดิม (!isExistingMember) จะถูกบล็อกทันทีด้วย Modal: "⛔ ไม่สามารถเข้าห้องสอบได้ในขณะนี้ - การสอบได้เริ่มต้นขึ้นแล้ว (Exam in Progress)"
เหตุผลทางสถาปัตยกรรม: เพื่อรักษาลำดับการวนสถานี (Rotation Order), ป้องกันตัวหารคะแนนของรุ่นคลาดเคลื่อน, และรักษาความเป็นธรรมของผู้เข้าสอบทุกคน if ((room.status === 'running' || room.status === 'countdown') && !isExistingMember)
13. เครือข่ายอินเทอร์เน็ตขัดข้องระหว่างสอบ Offline Guarantee
กลไกสำรอง: ข้อมูลเคสและเกณฑ์การตรวจทั้งหมดถูกบรรจุอยู่ใน case-details-offline.js (10MB+) เรียบร้อยแล้ว
ผลลัพธ์: การเปิดโจทย์, รูปภาพ, รายการตรวจ และการจับเวลาในเครื่องสามารถดำเนินต่อไปได้โดยไม่ต้องพึ่งพาเซิร์ฟเวอร์ภายนอก
14. นโยบายเสียงเตือน (Browser Audio Policy) Audio Engine
ข้อจำกัดเบราว์เซอร์: เบราว์เซอร์สมัยใหม่จะบล็อกการเล่นเสียงหากผู้ใช้ยังไม่ได้มีปฏิสัมพันธ์กับหน้าเว็บ (User Gesture)
วิธีแก้ปัญหาในระบบ: ฟังก์ชัน unlockAudioContext() จะถูกเรียกทันทีเมื่อผู้ใช้คลิกปุ่ม Start Exam หรือเลือกบทบาทในห้องรอ
15. การใช้งานกระดานทดดิจิทัล (Scratchpad) Tool Logic
การทำงาน: กระดานทดเป็น Client-side canvas อิสระของผู้เข้าสอบแต่ละคน ไม่ส่งข้อมูลผ่าน WebSockets เพื่อประหยัด Bandwidth
การรีเซ็ต: กระดานทดจะถูกรีเซ็ตหรือบันทึกภาพอัตโนมัติเมื่อมีการเปลี่ยนสถานีสอบ
16. ขีดจำกัดดาวน์โหลด Firebase (360 MB/วัน) Quota Safety
กลไกประหยัด Bandwidth: ระบบใช้ Throttling ในการบันทึกคะแนน (300ms) และแยกข้อมูลเคสขนาดใหญ่ (10MB+) ไปไว้ในออฟไลน์ไฟล์ ไม่ดึงผ่าน Firebase
ความปลอดภัย: Firebase รับส่งเฉพาะตัวเลขตัวจับเวลา สถานะห้องสอบ และ Array คะแนนขนาดเล็ก ทำให้รองรับนิสิตทั้งรุ่นได้ตลอดทั้งวันโดยไม่แตะเพดานโควตา

📊 ตารางเปรียบเทียบเชิงลึก: 4 โหมดการสอบใน PLE-CC Simulation

วิเคราะห์ความแตกต่างของสถาปัตยกรรม การควบคุมตัวจับเวลา การบันทึกคะแนน และพฤติกรรมของแต่ละโหมด

คุณลักษณะ / มิติ 1. Solo Practice Mode 2. Standard Room Mode 3. Cohort Breakout Mode 4. Carousel Rotation Mode
กลุ่มเป้าหมายการใช้งาน นิสิตฝึกซ้อมเดี่ยวที่บ้าน สอบตัวต่อตัว (1 นศ. + 1 กรรมการ) สอบจำลองทั้งรุ่นพร้อมกัน (Super Host + โต๊ะย่อย) สอบหมุนเวียนฐาน (กรรมการนั่งประจำฐาน)
การควบคุมตัวจับเวลา Client-side ภายในเครื่อง (startTimer) Server Epoch Timestamp ผ่าน Firebase Super Host สั่งจับเวลากลางผ่าน Firebase Super Host สั่งรอบกลางผ่าน Firebase
การเปลี่ยนสถานี นิสิตกด Next/Prev หรือหมดเวลาอัตโนมัติ Host หรือ Examiner กดเปลี่ยนสถานี Super Host สั่งเปลี่ยนพร้อมกันทุกโต๊ะ Super Host สั่งเปลี่ยนรอบหมุนเวียน
การบันทึกคะแนน บันทึกลงหน่วยความจำเครื่อง (LocalStorage) บันทึกลง rooms/[id]/scoresByStation บันทึกลง breakouts/[tableId]/scores/[stNum] บันทึกลง participantScores/[pId]/stations/[stNum]
ผลกระทบจาก Race Condition ไม่มีผลกระทบ (ไม่ใช้ Firebase) มีโอกาสต่ำ (ถ้าห้องเล็ก) ความเสี่ยงสูงสุด (เกิดบั๊กที่พบในสัปดาห์ 2) ความเสี่ยงปานกลาง
ระบบดูย้อนหลัง (Local Review) กดปุ่ม Prev ดูย้อนหลังได้อิสระ กดปุ่ม Prev ดูย้อนหลังได้ ต้องใช้ Local Review Mode ใหม่ (เฟส 2) กรรมการอยู่ประจำฐานเดิมตลอดเวลา
การสรุปผลคะแนน ประเมินตนเอง แสดงเกรดทันที สรุปผลหลังสอบเสร็จรายบุคคล สรุปผลแยกรายโต๊ะ + Podium รวมทั้งห้อง สรุปผลคะแนนหมุนเวียนครบทุกสถานี
